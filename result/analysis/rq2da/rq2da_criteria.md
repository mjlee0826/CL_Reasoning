## 1. 目的

RQ2 的結果 13：弱模型（gpt4omini、qwen）的候選改由強模型（deepseek4.1flash、gemini3.1flashlite）裁決，正確率比自己裁決高 2.47pp（95% 區間 1.65 到 3.29，8/8 個區塊為正）。

本實驗要回答：強裁判是真的在比較兩份候選，還是它自己本來就會這題？做法是在同一批題目上，比較「強模型從弱模型的兩份候選中挑一份」和「強模型自己直接作答」。

## 2. 資料

- 弱模型（產生候選）：g ∈ {gpt4omini, qwen}。
- 強模型（裁判或直接作答）：s ∈ {deepseek4.1flash, gemini3.1flashlite}。
- 不納入舊的 DeepSeek V3.2（`deepseek`）與 Gemini 2.5（`gemini`）。
- 資料集：mmlu、mathqa、truthfulqa、commonsenseqa。
- 配對（與 RQ2 相同）：EN+ZH（`L:en`、`L:zh`）、EN+S1（`L:en`、`S:T1.0:seed1`）、P1+P2（`P:expert`、`P:skeptic`）。
- 題目（與 RQ2 相同）：
  - 只取 both_answered，也就是 g 的兩條 path 都有解析出答案（`parse_ok` 為 True）的題目。
  - 不一致題 = 兩條 path 的答案不同的題目，用該資料集的 `compareTwoAnswer` 比較。

- 強模型的直接作答：
  - 來源是 `result/arms/{s}/{資料集}/L_en.json` 的 `parsed_answer`。

  - 計分與 RQ2 相同：最終答案是被選中那條 path 的答案；沒有有效選擇或被供應商擋下時，答案為空，算錯。
- g 自己裁決自己（Sys_self）：用 RQ2 判定時實際採用的版本，也就是 `result/analysis/rq2/cross_cells.csv` 中 `used_in_analysis` 為 True 的那一份。

  - qwen：主網格（`source` = `main_grid`），檔案在 `result/aggregations/qwen/{資料集}/judge__{配對}.json`。
- 第 6.8 節的 4×4 表也用 RQ2 實際採用的版本：
  - 非對角線的格子用 RQ2 的交叉檔。
  - 對角線：gpt4omini、deepseek4.1flash、gemini3.1flashlite 用 RQ2 的重跑版，qwen 用主網格。

## 3. 定義

一格 = 弱模型 g × 強模型 s × 資料集 × 配對，共 2 × 2 × 4 × 3 = 48 格。每一格都只在 g 的 both_answered 題目上計算。

### 3.1 五種系統的正確率

| 名稱 | 兩條 path 答案相同的題目 | 兩條 path 答案不同的題目 |
| --- | --- | --- |
| Sys_J | 採用共同答案 | 採用 s 當裁判挑出的答案（RQ2 交叉檔） |
| Sys_D | 採用共同答案 | 採用 s 自己的 L:en 答案 |
| Sys_self | 採用共同答案 | 採用 g 自己當裁判挑出的答案（第 2 節的版本） |
| Strong_alone | 一律用 s 自己的 L:en 答案 | 一律用 s 自己的 L:en 答案 |
| Weak_EN | 一律用 g 的 L:en 答案 | 一律用 g 的 L:en 答案 |

- 答對 = 該資料集的 `compareTwoAnswer(gold, 答案)` 為 True。空答案一律算錯。
- Diff = Sys_J − Sys_D，單位是百分點（pp）。

### 3.2 只在不一致題上算的量

- a：s 當裁判的正確率。
- b：s 自己 L:en 答案的正確率。
- agree：s 當裁判選出的答案，和 s 自己 L:en 答案相同的比例。
  - 只有兩邊都有答案、且 `compareTwoAnswer` 為 True 時才算相同。
  - 兩邊都是空答案不算相同。
- d：不一致題占 both_answered 題目的比例。

### 3.3 恆等式

Sys_J − Sys_D = d × (a − b)。兩邊都以正確率為單位，每一格核對，誤差超過 1e-9 就停。

## 4. 統計與判定

- 統計單位是區塊 = 弱模型 × 資料集，共 8 個。
- 每個區塊先對 2 個強模型 × 3 個配對的 6 格取平均，6 格等權。
- 跨 8 個區塊報：平均、SE（= 標準差 / √8）、95% t 區間（自由度 7）、幾個區塊為正。計算用 `Analysis.blockStats.summarize`，與 RQ1-K、RQ1-KJ、RQ2 相同。
- 門檻：**0.5pp**（暫定值，確認本檔時一併確認）。
- 狀態有四種，都是先對區塊取平均再和門檻比：
  - 正向成立：平均 ≥ +0.5pp，且 95% 區間不含 0。
  - 反向成立：平均 ≤ −0.5pp，且 95% 區間不含 0。
  - 兩者相當：整個 95% 區間落在 [−0.5, +0.5] 之內。
  - 無法判定：其他情況。

### 判定一（唯一參與判定的一項）：Diff = Sys_J − Sys_D

- 正向 = 強模型從候選中挑，比它自己直接作答好。
- 反向 = 強模型自己直接作答比較好。

事先寫下的讀法：

- 正向成立：弱模型的候選對強模型有幫助。可以把「弱模型作答、答案不同時交給強模型裁決」寫成建議，並報幅度。
- 反向成立：裁決這一步沒有價值。結果 13 的 2.47pp 只當診斷（瓶頸在裁判），不當建議；答案不同時直接讓強模型作答比較好。
- 兩者相當：裁決和直接作答的正確率相當（差距在 ±0.5pp 內）。論文寫「裁判這一步在正確率上沒有額外好處」，選哪一個由成本決定。
- 無法判定：只報區間，不提出建議。

其餘的量都只報告，不參與判定。結果不如預期時，不改定義、門檻、配對或模型。

### 6.1 總表

  - Sys_D − Sys_self
  - Sys_J − Sys_D
  - Strong_alone − Sys_J

### 6.2 不一致題上的 a、b、agree、d

- 分組：整體、分強模型、分弱模型、分配對、分資料集。
- 每組的值是該組各格的等權平均（整體 = 48 格的平均），並列出該組的不一致題總數。

### 6.3 依強模型自己的答案落在哪裡分三類

把不一致題分成三類，各報題數比例、a、b：

1. s 的 L:en 答案等於其中一個候選的答案，且裁判選了那個候選。
2. s 的 L:en 答案等於其中一個候選的答案，但裁判沒有選它。這包括裁判選了另一個候選，也包括裁判沒有給出有效選擇；後者的題數另外列出。
3. s 的 L:en 答案和兩個候選都不同，包括 L:en 沒有答案的情況。

不一致題上兩個候選的答案不同，所以 L:en 最多等於其中一個。題數、比例、a、b 都用題目合併計算（不是對格平均），報整體與分強模型。

### 6.4 依候選的對錯分兩類

不一致題分成兩類，各報題數比例、a、b：

- 兩個候選剛好一對一錯。
- 兩個候選都錯。此時裁判只能選其中一個，所以 a 必為 0。

題目合併計算，報整體與分強模型。

### 6.5 逐題對照

只算不一致題，報四格的題數：裁判對且直接答對、裁判對而直接答錯、裁判錯而直接答對、兩者都錯。題目合併計算，報整體與分強模型。

### 6.6 強模型 L:en 沒有答案

- 不一致題中，s 的 L:en 沒有答案的題數與比例，報整體與分強模型 × 資料集。
- 敏感度（不參與判定）：每一格排除這些題目後重算 Diff，報 8 個區塊的平均、95% t 區間與為正的區塊數。

### 6.7 呼叫強模型的成本

- 呼叫次數：
  - Sys_J 與 Sys_D 都只在不一致題上呼叫強模型，比例是 d。
  - Strong_alone 每題呼叫一次。
- 每次呼叫的平均 input 與 output tokens，分強模型報。
  - 裁判的呼叫：RQ2 交叉檔中不一致題的紀錄。
  - 直接作答的呼叫：s 的 L:en 紀錄，在同一批不一致題上（Sys_D），以及在 both_answered 全部題目上（Strong_alone）。
  - 兩者都用每題紀錄中重算的 tokens（`tokens_in`、`tokens_out`）。arm 紀錄只有重算值，這樣兩者才能比較。
  - 裁判呼叫另外列出 API 計費的 tokens（`call.usage_in`、`call.usage_out`）。
  - 平均以每次呼叫計，題目合併計算。

### 6.8 參考用的 4×4 表（只當附錄，不做判定）

- 列 = 產生候選的模型，欄 = 裁判的模型，4 個模型都在列和欄上，含自己裁決自己；檔案版本見第 2 節。
- 每一格報不一致題上的 a、b、agree，b 與 agree 用的是該裁判模型自己的 L:en 答案。每一格的值是 4 個資料集 × 3 個配對共 12 格的等權平均。
- 自己裁決自己的格子要註明：EN+ZH 與 EN+S1 中，L:en 本身就是候選之一。
