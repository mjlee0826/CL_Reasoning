## 1. 目的

RQ3 問：K 條 path 中，該換掉或拿掉哪一條？本實驗用 RQ1-K 的逐題資料回答兩件事：

1. 用一半題目選出一條 path 拿掉，另一半題目上的多數決有沒有變好。
2. 拿掉兩條 persona（P:expert、P:skeptic）之後，多數決相對於「菜單內最強的單一 path」的增益有沒有變大。

第 2 項直接檢驗 RQ1-K 的說法：增益大小取決於菜單裡有沒有強的 path。

## 2. 資料與菜單

- 模型：gpt4omini、qwen、deepseek4.1flash、gemini3.1flashlite。不納入舊的 DeepSeek V3.2（`deepseek`）與 Gemini 2.5（`gemini`）。
- 資料集：mmlu、mathqa、truthfulqa、commonsenseqa。
- 區塊 = 模型 × 資料集，共 16 個。
- 來源：`result/arms` 的逐題答案，用 `Analysis.menuVote.loadPathBlock` 載入，與 RQ1-K 相同。它會讀 14 個 path 檔，這裡只用 M12 的 12 條。
- path 代號：

| --- | --- |
| EN | L:en |
| ZH | L:zh |
| JA | L:ja |
| RU | L:ru |
| ES | L:es |
| S1 | S:T1.0:seed1 |
| S2 | S:T1.0:seed2 |
| P1 | P:expert |
| P2 | P:skeptic |

| W2 | W:rewrite2 |

- 菜單：
  - M12：和 RQ1-K 相同的 12 條。
  - M12−p：M12 去掉一條 p，共 12 份，每份 11 條。
  - M10：M12 去掉 P1 與 P2。
  - 只報告用的「M12 只去掉 P:skeptic」就是 M12−P2，「M12 只去掉 P:expert」就是 M12−P1。兩份都已在 M12−p 之中，不另外計算，報告中標明對應關係。
- 題目子集：
  - 所有菜單都用同一批題目：M12 的 12 條 path 都有答案（`parse_ok` 為 True）的題目。這就是 RQ1-K 算 M12 的 Excess_in 時用的子集，所以拿掉 path 前後比的是同一批題目。
  - 這和 RQ1-K 算其他菜單的做法不同。RQ1-K 對每份菜單用「該菜單的 path 都有答案」的題目；本實驗不這樣做。
- 多數決與平手：和 RQ1-K §3.1 完全相同，用同一個函式 `Analysis.menuVote.vote`，只是菜單內的 path 變少。
  - 答案相同與否用該資料集的 `compareTwoAnswer` 判斷；票數最高的答案只有一個時就取它。
  - 平手（最高票數由兩個以上的答案共有）時，依優先順序找第一條答案落在平手答案中的 path，取它的答案。
  - 優先順序：EN、ES、JA、P1、P2、R、RU、S1、S2、W1、W2、ZH。菜單裡沒有的 path 直接跳過。
  - 子集內每條 path 都有答案，所以不會出現「沒答案的 path 不投票」的情況。
- 切分：
  - 用 `makeSplits(n, 200, seed=0)`，同一資料集的所有模型共用（`Analysis.menuJudgeStats.blocksWithSplits`），與 RQ1、RQ1-K、RQ1-KJ 相同。
  - 第 r 次切分把題目分成 H1_r 與 H2_r。挑選都在 H1_r ∩ 子集上做，評分都在 H2_r ∩ 子集上做。

## 3. 定義

以下都是對每一次切分、每一個區塊計算。

- A_V(M)：菜單 M 的多數決在 H2 ∩ 子集上的正確率。
- S_in(M)：在 H1 ∩ 子集上，選出菜單 M 內答對題數最多的 path，報它在 H2 ∩ 子集上的正確率。
  - 平手時依第 2 節的優先順序（EN 優先，其餘依代號字母序），即 RQ1-K 的 `Analysis.probe.strongest`。
- Excess_in(M) = A_V(M) − S_in(M)。

### 3.1 第一部分：拿掉一條

- p\*：在 H1 ∩ 子集上，讓 M12−p 的多數決答對題數最多的那條 p。比的是整數題數，避免浮點誤差造成的假平手。
- 平手時，拿掉在優先順序中排得較後的那條。所以拿掉的先後依序是：ZH、W2、W1、S2、S1、RU、R、P2、P1、JA、ES、EN。L:en 最後才會被拿掉。
- Prune1 = A_V(M12−p\*) − A_V(M12)，兩者都在 H2 ∩ 子集上算。

### 3.2 第二部分：拿掉兩條 persona

- ΔA = A_V(M10) − A_V(M12)
- ΔS = S_in(M10) − S_in(M12)
- ΔExcess = Excess_in(M10) − Excess_in(M12) = ΔA − ΔS

### 3.3 單位與限制

- 每個區塊的值是 200 次切分的平均，以百分點（pp）表示。
- 不用「在 H2 上從所有 path 或所有菜單中挑最大值」當任何基準。

## 4. 統計與判定

- 統計單位是區塊。跨 16 個區塊報平均、SE（= 標準差 / √16）、95% t 區間（自由度 15）、幾個區塊為正。計算用 `Analysis.blockStats.summarize`，與 RQ1-K、RQ1-KJ、RQ2 相同。
- 門檻：**0.5pp**（暫定值，確認本檔時一併確認）。
- 狀態有四種，都是先對區塊取平均，再和門檻比：
  - 正向成立：平均 ≥ +0.5pp，且 95% 區間不含 0。
  - 反向成立：平均 ≤ −0.5pp，且 95% 區間不含 0。
  - 兩者相當：整個 95% 區間落在 [−0.5, +0.5] 之內。
  - 無法判定：其他情況。

參與判定的只有判定一和判定二。其餘都只報告。結果不如預期時，不改定義、門檻或菜單。

### 判定一：Prune1

- 正向 = 拿掉選出的那一條後，多數決變好。反向 = 變差。
- 事先寫下的讀法：
  - 正向成立：修剪菜單有好處。主張一要補一句「挑對成員可以再多 X」，X 是 Prune1 的平均。
  - 反向成立：用標註選一條拿掉，反而讓多數決變差。
  - 兩者相當：拿掉一條對多數決幾乎沒有影響（±0.5pp 內）。
  - 無法判定：只報區間。

### 判定二：ΔExcess

- 正向 = 拿掉 persona 後，多數決相對於菜單內最強 path 的增益變大。
- 事先寫下的讀法：
  - 正向成立：支持「增益大小取決於菜單裡有沒有強的 path」。
  - 反向成立或兩者相當：這個說法不成立，論文裡對應的句子要改寫。
  - 無法判定：只報區間，這個說法只能寫成觀察。

## 7. 另外要報告的量（不參與判定）

1. 判定一、二的逐區塊數字，以及分資料集、分模型的平均。
2. p\* 是哪一條：
   - 每個區塊在 200 次切分中，各 path 被選為 p\* 的比例。
   - 依類別合計：語言（ZH、JA、RU、ES）、L:en（EN）、採樣（S1、S2）、persona（P1、P2）、改寫（W1、W2）、簡短 CoT（R）。
3. 不經挑選的逐條結果：
   - 對每一條 p，用子集內全部題目（不切分）算 A_V(M12−p) − A_V(M12)，以百分點表示。
   - 報 16 個區塊的平均、95% t 區間與為正的區塊數。
   - 註明這是 12 個比較，只當描述。
4. 「可以選擇不拿」的版本：
   - 在 H1 ∩ 子集上，從「不拿（M12）」與 12 種拿法共 13 個選項中，選答對題數最多的一個。平手時優先選不拿；只有幾種拿法之間平手時，依第 3.1 節的順序。
   - 報它在 H2 ∩ 子集上相對於 A_V(M12) 的差（16 個區塊的平均、95% t 區間、為正的區塊數），以及選到「不拿」的切分比例（逐區塊與平均）。
5. 第二部分的組成：
   - A_V(M12)、A_V(M10)、S_in(M12)、S_in(M10)、ΔA、ΔS，各附 16 個區塊的平均與 95% t 區間。
   - S_in(M10) 最常選到哪一條 path：逐區塊列出前兩名與它們在 200 次切分中的比例。
6. A_V(M10) − S_in(M12)：沒有 persona 的多數決，對上 12 條中最強的單一 path。報 16 個區塊的平均、95% t 區間與為正的區塊數。
7. M10 的分解，和 M12 並列，兩者都在 M12 的子集上算，定義與 RQ1-K 相同。每次切分在 H2 ∩ 子集上計算：
   - d = 菜單內各 path 答案不完全相同的題目（不一致題）所占的比例。
   - c = 不一致題中至少一條 path 答對的比例。
   - m = 不一致題上各 path 答對比例的平均。
   - headroom = d × (c − m)。
   - recovery_V = (多數決在不一致題的正確率 − m) / (c − m)。
   - recovery_blind = (S_in 在不一致題的正確率 − m) / (c − m)。
   - 每次切分核對恆等式 Excess_in = d × (c − m) × (recovery_V − recovery_blind)，誤差 ≤ 1e-9；不符就停。
   - 沒有不一致題、或 c ≤ m 的切分，recovery 無定義。這時 Excess_in 必須為 0（同樣核對），並報無定義的切分次數。
8. 只去掉 P:skeptic（M12−P2）、只去掉 P:expert（M12−P1）的 A_V、S_in、Excess_in，和 M12、M10 並列。
