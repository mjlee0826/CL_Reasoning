## 1. 目的

目前的「聚合」都只用兩條 path。全域基準拿「兩條的聚合」去比「14 條中最強的一條」，對聚合不公平。RQ1-K 在同一份菜單（一組 path）內比較「全部一起聚合」與「最強的單一 path」。它回答三件事：

1. 論文的主張「聚合很少贏過單一最強 path」在公平比較下是否成立。
2. 「要不要聚合」的決策有沒有空間，值不值得再做一次 RQ1。
3. 同樣用三條 path 時，換語言有沒有比同語言重抽好。

聚合方式只有多數決。

## 3. 定義

### 3.1 聚合（多數決）與平手

- 聚合答案 = 菜單內各 path 解析出的答案中，得票最多者。
- path 優先順序固定為：EN、ES、JA、P1、P2、R、RU、S1、S2、SR-EN、SR-ZH、W1、W2、ZH。
  - 即 L:en 第一，其餘依 path 代號字母序；與 RQ1 的 `Analysis.probe.pathKey` 相同。
- 平手（最高票數由兩個以上的答案共有）時，依優先順序找第一條答案落在平手答案中的 path，取它的答案。
- 平手比例 = 子集內發生平手的題目比例。每個區塊、每個菜單都報。

### 3.2 題目子集

- 子集_in(菜單)：菜單內所有 path 都有答案的題目。用於 Excess_in。
- 子集_all：M12 的 12 條 path 都有答案的題目。用於 Excess_all，所有菜單共用。
- 保留比例 = 子集題數 ÷ 資料集題數。每個區塊、每個菜單都報。
- M14 的 Excess_all：子集_all 中，F:en 或 F:zh 沒有答案的題目，該 F path 不參與投票（與 §5.6 的規則相同）。

### 3.3 切分

- 每個資料集用 `Analysis.splitHalf.makeSplits(n_d, reps=200, seed=0)`，與 RQ1 相同。
  - n_d = 資料集題數：truthfulqa 817，其餘 2000。
  - 同一個亂數產生器依序產生 200 次切分。
  - 第 r 次得到 H1_r、H2_r；同一資料集的所有模型與菜單共用。
- 每次切分再和題目子集取交集：選擇只用 H1_r ∩ 子集，評估只用 H2_r ∩ 子集。

### 3.4 每次切分的量（正確率）

- A：菜單聚合答案在 H2_r ∩ 子集上的正確率。
- S_in：在 H1_r ∩ 子集_in 上，菜單內答對最多的 path（平手依 §3.1 的優先順序）。它在 H2_r ∩ 子集_in 上的正確率。
- S_all：在 H1_r ∩ 子集_all 上，M12 的 12 條中答對最多的 path（平手同上）。它在 H2_r ∩ 子集_all 上的正確率。
- EN：L:en 在 H2_r 上的正確率，當參考。兩個子集各報一個。

### 3.5 每個區塊的 Excess（百分點）

- Excess_in = A − S_in，在子集_in 上。
- Excess_all = A − S_all，在子集_all 上。
- 兩者都先對 200 次切分取平均。
- M12 的子集_in 等於子集_all，所以 S_in 與 S_all 相同。程式核對這一點，不相同就停。

## 4. 統計與判定（門檻 0.5pp 為暫定值，確認時一併確認）

### 4.1 統計量

- 統計單位是區塊。跨 16 個區塊報四個量：
  - 平均
  - SE = sd / √16
  - 95% t 區間（自由度 15）
  - 幾個區塊為正

### 4.2 四種狀態

| 狀態 | 條件 |
|---|---|
| 正向成立 | 平均 ≥ +0.5pp，且 95% 區間不含 0 |
| 反向成立 | 平均 ≤ −0.5pp，且 95% 區間不含 0 |
| 兩者相當 | 整個 95% 區間落在 [−0.5, +0.5] 之內 |
| 無法判定 | 其他情況 |

### 4.3 判定一（主張是否成立）

- 量：M12 的 Excess_in。
- 正向 = 聚合較好；反向 = 單一最強較好。

### 4.4 判定二（決策空間，go / no-go）

只用 M12。

- E_b = 區塊 b 的 Excess_in（對 200 次切分的平均，百分點）。
- 永遠聚合的 regret = 16 個區塊的 max(0, −E_b) 的平均。
- 永遠用單一最強的 regret = 16 個區塊的 max(0, E_b) 的平均。
- 空間 = 兩個 regret 取較小者。
- 判定：
  - 空間 ≥ 0.5pp：值得再做一次 RQ1（另外寫判定標準，這次不做）。
  - 空間 < 0.5pp：RQ1 維持負面結果。
- 不使用「在 H2 上從所有 path 挑最大值」的 Oracle 計算空間，那樣會嚴重高估。

### 4.5 判定三（同 K 的來源比較）：M3S 對 M3L

- 題目：EN、ZH、JA、S1、S2 五條都有答案的題目。兩個菜單在同一批題目上比，切分同 §3.3。
- 每個區塊：M3S 聚合在 H2_r 上的正確率 − M3L 聚合在 H2_r 上的正確率，對 200 次切分平均，百分點。
- 正向 = 同語言重抽較好；反向 = 換語言較好。

### 4.6 範圍限制

- 以上判定只針對「多數決」這一種聚合方式。
- 「聚合是否贏過單一最強 path」的一般性結論，要等同一份菜單上的 Judge 版本（看全部候選後挑一個）完成後才能下。
- 判定一的結果若是「反向成立」「兩者相當」或「無法判定」，Judge 版本列為必要的後續實驗；若是「正向成立」，列為可選。
- 其他菜單的 Excess_in、Excess_all 與各自的空間（算法同 §4.4）都報告，但不參與判定。若只有非主要菜單的空間 ≥ 0.5pp，標為探索性，不算通過 go / no-go。

## 5. 另外要報告的量（不參與判定）

1. **總表**：列 = 菜單；欄 = 聚合正確率、S_in、S_all、EN、Excess_in、Excess_all（兩個 Excess 各附 95% 區間與為正的區塊數）。
2. **逐區塊與彙總**：每個菜單的逐區塊數字；分資料集、分模型的平均。
3. **被選中的 path**：S_in、S_all 在 H1 上最常選中哪條 path。每個區塊列前兩名與被選中的比例（200 次中幾次）。
4. **K 條 path 的分解**（每個菜單，用 S_in；每次切分在 H2_r ∩ 子集_in 上計算）：
   - d：菜單內 path 答案不完全一致的題目比例。
   - c：這些題目中至少一條 path 答對的比例。
   - m：這些題目上各 path 的平均正確率（對 path 與題目平均）。
   - headroom = d·(c − m)。
   - recovery = （聚合在這些題目的正確率 − m）÷（c − m）。
   - recovery_blind = （S_in 在這些題目的正確率 − m）÷（c − m）。
   - 每次切分核對 Excess_in = headroom ×（recovery − recovery_blind），以正確率為單位、誤差 ≤ 1e-9；不符就停下來回報。
   - 沒有分歧題（d = 0）或 c = 0 時，recovery 無定義。這時核對改為 Excess_in = 0，並報告這種切分的次數。
   - 各量報對切分的平均（無定義的切分不計入）。
5. **成本**：
   - 每題的呼叫次數：菜單大小對 1。多數決沒有額外的聚合呼叫。
   - 輸出 tokens：每題菜單內各 path 輸出 tokens 的總和，對 S_in 那條 path 的輸出 tokens（對切分平均）。
6. **敏感度**：
   - 題目子集改成全部題目：
     - 沒答案的 path 不參與多數決；所有 path 都沒答案時，聚合沒有答案、算錯。
     - 單一 path 沒答案算錯。
     - S_in、S_all 改在 H1_r 的全部題目上選。
   - 平手改成隨機：每題用 `numpy.random.default_rng([0, item_id])` 在平手答案中均勻抽一個。平手答案依 §3.1 的優先順序排列。
   - M14 的結果。
7. **與 RQ1 全域基準比對**：
   - 逐區塊比較 M14 的 S_in，和 RQ1 `result/analysis/rq1/blocks.csv` 中全域基準的 acc_S（Judge、隨機 probe、k = 500，對該區塊的格子平均）。
   - 預期接近但不相同：RQ1 只用 H1 的 500 題選 path、在各配對的 both_answered 子集上評估；這裡用整個 H1 ∩ 子集_in。
   - 平均差距超過 0.5pp 時逐區塊說明原因。
