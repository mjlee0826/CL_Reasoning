# 核對二：沒有答案的輸出是什麼原因

產生時間：2026-10-05 15:08 CST；程式：`scripts/parse_failures.py`。不呼叫 API，不修改任何現有檔案。

## (1) 讀了哪些檔案與欄位

- `result/arms/{模型}/{資料集}/` 的 M12 12 個 path 檔（`L_en.json`、`L_zh.json`、`L_ja.json`、`L_ru.json`、`L_es.json`、`S_T1.0_seed1.json`、`S_T1.0_seed2.json`、`P_expert.json`、`P_skeptic.json`、`W_rewrite1.json`、`W_rewrite2.json`、`R_short_cot.json`），4 模型（gpt4omini、qwen、deepseek4.1flash、gemini3.1flashlite）× 4 資料集，共 192 個檔；不含 F_en、F_zh，也不含 result/arms/deepseek（舊的 V3.2）與 result/archive（Gemini 2.5）。
- 逐筆欄位：`parse_ok`（False = 沒有答案，即解析結果是空的、"null" 或 "None"，與 RQ1-K / RQ1-KJ 保留題目時相同）、`raw_text`、`tokens_out`、`item_id`；檔頭的 `refusals`（供應商擋下的題目）。
- **沒有 `finish_reason` 欄位**：arm 紀錄不存它，檔頭的 `api_usage` 只有整檔總數。所以「寫到 token 上限」只用「輸出 tokens ≥ 8,000」一個條件；finish_reason = length 的數量無法列出。`tokens_out` 是用各模型的 tokenizer 對輸出文字重算的數（GPT / Qwen 的舊結果匯入時重算；DeepSeek 與 API 回報相同；Gemini 用 count_tokens，與 API 差幾個 token）。四個模型的 max_tokens 都是 8,192。
- 「有重複迴圈」：輸出中某一段 50 個字元的片段，不重疊地出現 5 次以上（更長的重複片段一定含一個重複的 50 字元片段，所以只查 50 字元）。只對沒有答案的輸出計算。
- 原因分類：先看是否寫到上限；其餘（沒有寫到上限）依序判斷 ——
  - 輸出為空或被供應商擋下：`raw_text` 是空的，或題目列在檔頭的 `refusals`；
  - 有輸出但格式不符：輸出裡沒有 `{"…": "…"}` 形式的答案 JSON（解析器 `Strategy.parseAnswer` 找的就是它）；
  - 其他：有答案 JSON，但值是空白、"None" 或 null（模型表明選項中沒有答案）。這不是解析規則的問題。
